## Overview

Finance and operations teams waste hours manually re-typing inconsistent vendor documents into spreadsheets. This leads to:

- **Typos** from manual data entry
- **Duplicate payments** when the same invoice is processed twice
- **Tax calculation errors** from inconsistent number formatting

**Doc2DB-AI** solves this by providing:

1. A **smart text extraction engine** that parses unstructured `.txt` invoice documents and normalizes them into structured data
2. A **structured JSON ingest API** for AI agents (like IBM Bob) that have already extracted data from documents
3. A **validation engine** that cross-checks line-item math and flags discrepancies
4. A **duplicate guard** that prevents the same invoice from being inserted twice
5. An **interactive web dashboard** for reviewing, searching, and exporting records
6. A **full audit trail** of every ingestion attempt

## Quick Start

```bash
# 1. Clone the repository
git clone https://github.com/<your-username>/Doc2DB.git
cd Doc2DB

# 2. Initialize the database
python app.py --init-db

# 3. (Optional) Ingest sample documents to populate with test data
python app.py --ingest samples/sample1_valid.txt
python app.py --ingest samples/sample2_math_discrepancy.txt
python app.py --ingest samples/sample3_duplicate.txt

# 4. Start the dashboard
python app.py --serve

# 5. Open in browser
# → http://localhost:8080
```

You can also combine init and serve in one command:

```bash
python app.py --init-db --serve
```

## CLI Reference


## API Reference

All endpoints are served at `http://localhost:8080`. No authentication is required (see disclaimer above).

### `GET /`
Serves `index.html` — the web dashboard.

---

### `GET /api/kpi`
Returns summary KPI counts.

**Response `200`:**
```json
{
  "total_invoices":   2,
  "total_pengeluaran": 85026000.0,
  "verified":         1,
  "needs_review":     1
}
```

---

### `GET /api/invoices`
Returns all invoices joined with vendor names.

**Query parameters:**

| Param | Description |
|-------|-------------|
| `q` | Search string (matches vendor name or invoice number) |
| `status` | Filter by `VERIFIED` or `NEEDS_REVIEW` |

**Response `200`:** Array of invoice objects.

---

### `GET /api/invoice-items/<id>`
Returns line items for a given invoice ID.

**Response `200`:** Array of `{id, invoice_id, description, quantity, unit_price, line_total}`.

---

### `GET /api/logs`
Returns the last 200 ingestion log entries, newest first.

---

### `GET /api/export/csv`
Downloads all invoices as `invoices.csv`.

---

### `GET /api/export/sql`
Downloads all table data as INSERT statements in `finance_export.sql`.

---

### `GET /api/query?sql=<SELECT...>`
Runs a read-only SQL query against `finance.db`.

- Only `SELECT` statements are accepted (HTTP 403 otherwise)
- Blocked keywords: `DROP`, `DELETE`, `UPDATE`, `INSERT`, `ALTER`, `CREATE`, `ATTACH`, `PRAGMA`, `EXEC`

**Response `200`:**
```json
{ "columns": ["id", "invoice_number"], "rows": [[1, "INV-001"]] }
```

---

### `POST /api/extract`
Extracts structured data from raw document text (preview only — does not save).

**Request body:**
```json
{ "text": "...raw invoice text...", "source_name": "myfile.txt" }
```

**Response `200`:**
```json
{ "ok": true, "data": { ...extracted fields + validation_status + validation_notes... } }
```

---

### `POST /api/ingest-json`
Saves a structured invoice JSON object to the database.

**Request body:** See [AGENTS.md](AGENTS.md) for the full schema.

**Response codes:**

| HTTP | `status` | Meaning |
|------|----------|---------|
| 200 | `VERIFIED` | Saved, math OK |
| 200 | `NEEDS_REVIEW` | Saved with warnings |
| 200 | `DUPLICATE_SKIPPED` | Already exists |
| 400 | `ERROR` | Missing required fields or DB error |

## Database Schema

```sql
-- Vendor master records
vendors (id, name UNIQUE, tax_id, address, created_at)

-- One row per invoice
invoices (
  id, vendor_id FK, invoice_number, invoice_date ISO-8601,
  due_date, currency, subtotal, tax_amount, total_amount,
  validation_status CHECK('VERIFIED'|'NEEDS_REVIEW'|'PENDING'),
  validation_notes, source_name, created_at,
  UNIQUE(vendor_id, invoice_number)
)

-- Line items (cascade-deleted with parent invoice)
invoice_items (id, invoice_id FK CASCADE, description, quantity, unit_price, line_total)

-- Full audit trail
ingestion_logs (id, source_name, invoice_number, status, message, processed_at)
```

Foreign keys are enforced (`PRAGMA foreign_keys = ON`) and the database uses WAL journal mode for better concurrent read performance.

## Document Extraction Engine

The raw text parser (`extract_from_text` in `app.py`) handles:

### Supported date formats

| Input | Normalized output |
|-------|------------------|
| `12 November 2026` | `2026-11-12` |
| `12 Nov 2026` | `2026-11-12` |
| `18/11/2026` | `2026-11-18` |
| `18-11-2026` | `2026-11-18` |
| `2026-11-18` | `2026-11-18` (passthrough) |
| `November 12, 2026` | `2026-11-12` |

Month names in both English and Bahasa Indonesia are recognized.

### Currency & amount normalization

| Input | Output |
|-------|--------|
| `Rp 34.600.000` | `34600000.0` |
| `Rp  5.000.000` | `5000000.0` |
| `IDR 1.500.000,50` | `1500000.5` |
| `$ 1,200.50` | `1200.5` |

### Field extraction labels recognized

| Field | Recognized labels |
|-------|------------------|
| Vendor name | First non-empty line, or after `Vendor:` / `Supplier:` / `Dari:` |
| Tax ID | `NPWP`, `Tax ID`, `No. Pajak` |
| Invoice number | `Invoice No.`, `Nomor Faktur`, `No. NF`, `No. Invoice` |
| Invoice date | `Tanggal`, `Invoice Date`, `Tgl.` |
| Due date | `Jatuh Tempo`, `Due Date` |
| Subtotal | `Subtotal`, `DPP`, `Harga Sebelum Pajak` |
| Tax | `PPN`, `VAT`, `Tax`, `Pajak` |
| Total | `Total Tagihan`, `Grand Total`, `Jumlah Total`, `Total Bayar` |

## Known Limitations & Recommended Tweaks

> **These are the most likely areas you will need to modify for your specific use case.**

### 1. Regex extraction is format-sensitive
The extraction engine uses regex patterns tuned for common Indonesian invoice layouts. Documents with unusual column spacing, non-standard labels, or complex multi-page layouts **will likely produce incomplete or incorrect extractions**.

**Recommended fix:** After calling `/api/extract`, always review the JSON preview in the dashboard before clicking "Simpan ke Database". For bulk ingestion, use the structured JSON path (see [`AGENTS.md`](AGENTS.md)) where an AI agent pre-extracts the data with higher accuracy.

### 2. Python 3.10+ type hint syntax
The code uses `str | None` union type hints which require **Python 3.10+**. On Python 3.9, change occurrences of `str | None` and `float | None` to `Optional[str]` and `Optional[float]` with `from typing import Optional` at the top of `app.py`.

### 3. No HTTPS / no authentication
The built-in `http.server` has no TLS support. **Never expose port 8080 to the internet**. For any networked deployment, put a reverse proxy (nginx, Caddy) with TLS and HTTP basic auth in front of it.

### 4. Single-writer SQLite concurrency
SQLite WAL mode handles multiple concurrent readers well, but **only one writer at a time**. For high-throughput ingestion pipelines, consider migrating to PostgreSQL and replacing `sqlite3` with `psycopg2`.

### 5. `finance.db` is unencrypted
All financial data is stored in plain text in `finance.db`. Use [SQLCipher](https://www.zetetic.net/sqlcipher/) or encrypt the volume/disk if storing sensitive data.

### 6. Vendor name extraction fallback
When no explicit `Vendor:` / `Supplier:` label is present, the engine uses the **first non-empty line** of the document as the vendor name. If your documents have headers or decorative lines before the company name, this will produce incorrect vendor names. Adjust the fallback logic in `extract_from_text()` in `app.py`.

### 7. No multi-page / PDF support
The parser only handles plain text (`.txt`). For PDF ingestion, use a tool like `pdfplumber` or `pymupdf` to extract text first, then pipe it through `/api/extract`.

### 8. Tax percentage auto-computation
If a document states only a tax percentage (e.g. `PPN 11%`) without the computed tax amount, the engine **does not auto-compute** the tax value from the percentage. Add this logic in the `extract_from_text()` function if needed.
